### 1. REF-* anchor class — INTAKE-READY under v0.3.1; no new schema shape gates Batch C
The 16 v5_24-only `REF-*` anchors (citation records into external literature) ride existing machinery — ID prefix is convention (not schema-enforced), `additionalProperties: true` carries the rest. **Posture requirements at intake:**
1. **`provenance_kind: theory-external`** — this enum value exists precisely for external-corpus citations. Not plain `theory`; the legacy `provenance: T` on these rows translates accordingly (decisions-file lane).
2. **Lift citations into the typed fields** — each REF-* SHOULD carry ≥1 of `theory_citation` / `theory_doi` / `theory_url` (v0.3 #71 fields) rather than embedding the citation only in description prose. Mechanical at apply-time.
3. **Status semantics:** on a citation record, `coherent` = **citation integrity** (source exists + is accurately characterized) — NOT endorsement of the cited result's role in QBP. The claim-content lives in the CONJ-/INSIGHT- anchors that `converges_with` them. Reading it this way keeps the SUBSTRATE-layer/NASCENT intake lens clean: a REF can be fully `coherent` while its dependent CONJ is `untested`.

A formal REF shape (per-class required-fields constraint) is **deferred** — queued with `physical_mapping_type` for the next canonical minor bump; not a Batch-C gate.

**Cross-surface note:** REF-* is the inventory-side analog of A23's `NT_LITERATURE_NODE` (BMA Theory v3.0 §2.4, §I4'd today — reference + provenance + locale anchor, full document never stored). At Walk these should map rather than diverge; naming the correspondence now prevents two citation-record shapes growing apart.

### 2. §3 `INST-ckm` row (my lane) — REJECT theirs; keep ancestor `tier: 1`
v5_24 sets `tier: 0`. **Out of domain**: canonical v0.3 constrains anchor tier to **[1,3]** (schema `minimum: 1, maximum: 3` + `Anchor.Validate`). Tier 0 is the Axiom layer; an irreducible input (CKM angles) is a tier-1 anchor (or an Input node), never an axiom. Adopting would make canonical fail its own validation.
