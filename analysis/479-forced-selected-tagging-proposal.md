## 1. Inclusion rule (AC1 scope, mechanical)

An `anchors[]` record is **numeric** iff at least one top-level field **other than** the bookkeeping fields `tier`, `sorry_count`, `pa_local`, `pa_effective` holds a number (int/float, never bool) or a list/dict with **at least one numeric leaf**. String-typed numbers do not count (the schema types `measured_value`/`predicted_value` as `number`). (v0.1 required *all* leaves numeric, which dropped `PRED-a0-redshift-linear` and `PRED-btfr-mass-correction`, whose numbers sit in a mixed `experimental_backing` dict — `F_max_best_fit = 13.378`, `delta_chi2_total = 72.89` — the very fit §3 names; Red Team G1.)

Why this and not "has `measured_source`": the issue's scope is anchors that *cite agreement with an external convention or measurement*. A field test on `measured_source` would miss records that carry the external number in `measured_value` with the citation in prose (`OBS-jades-gs-z14-0-vrot-lower-100`) and would include nothing the numeric test misses. The numeric test is the superset; rows with no external reference on record say so in the table (`— (none on record)`), so completeness is visible rather than filtered.

Fields observed carrying numbers (ledger 6.19.0): `predicted_value` (77), `measured_value` (78), `measured_error` (68), `discrepancy_pct` (39), `predicted_value_lo` (2), `predicted_value_hi` (1), `predicted_values` (1, dict), `F_max_value` (1), `prediction_at_z_14` (1), `synthetic_separation_sigma` (1), `experimental_backing` (4, mixed dict), `literature_constraints` (1, mixed).

**Scope note (Red Team G5):** the 5 R-MEAS rows and the 9 R-EXT rows carry *no QBP-side number*, so there is no "agreement" to tag; they are in the census because the inclusion rule is a superset, and the `basis` column (`measurement-only` / `external-datum`) says so.

## 2. Tag rules (first match wins; each cites a record field, never a physics judgement)

| Rule | Condition (record fields) | Tag | Why this is record-mechanical |
|---|---|---|---|
| **R-FIT** | `independent: false` **or** id prefix `FIT-` | SELECTED | the record declares itself a fit |
| **R-OVR** | id in the override table (§3.2) — a **verbatim quote** of a record field, verified at run time (drift = hard error) | per table | the quote *is* the record saying "scanned / best-fit / calibrated INPUT / analytic proof / IDENTIFICATION not prediction" |
| **R-INST** | the transitive `prediction_chain` closure reaches a free-parameter node: an `inputs[]` id (`INST-f0`, `INST-theta`, `INST-TcJ-ratio`, …), an `INST-` anchor, or an R-OVR-SELECTED anchor | SELECTED | `prediction_chain` is the ledger's own dependency edge (`pa_effective` is min over it, `docs/cth/qbp-local-extensions.md`); a fitted input upstream = a degree of freedom exercised. dof per anchor = distinct parameters reached |
| **R-EXT** | `prediction_chain: []` **and** `provenance_kind ∈ {experiment, theory-external}` **and no predicted-side field** | FORCED | the record holds only an imported number. A record with a *predicted-side* number and an empty chain falls through to `default`: an empty chain is absence of a *recorded* dof, not evidence of none (Red Team S1). Where the predicted number is the external theory's own, the record says so and R-OVR cites it (the 5 `REF-efimov-*`, `REF-jido…`, `EXT-omega-dm`) |
| **R-MEAS** | has `measured_value` and **no** predicted-side field (`predicted_value[_lo/_hi/s]`, `prediction_at_z_14`, `F_max_value`) | FORCED | external measurement only — nothing QBP-side to be forced or selected |
| **R-THM** | `provenance_kind: proof`, `lean_theorem`, `sorry_count: 0`, `verification.result: verified` | UNDECIDED | the theorem forces the *algebraic identity*; whether the *physical identification* was derived or chosen is not on record |
| **default** | otherwise | UNDECIDED | what decides it: a Lean derivation of the number from the chain ⇒ FORCED; a named selection step ⇒ SELECTED |

**Discipline.** The issue defines FORCED as "uniquely determined by the algebra". This proposal's FORCED is the wider "*no free choice on record* — fixed by an external measurement or external theorem"; to keep the two senses apart every row carries a **`basis`** (Red Team S4): `algebra-identity` · `external-theorem` · `external-datum` · `measurement-only` · `fitted-input` · `calibrated-input` · `candidate-scan` · `unruled`. **No row today is FORCED with an algebra basis** — that is the headline negative, and the schema proposal (§6) carries `basis_kind` so the ledger cannot blur it. "SELECTED" means *the record itself shows a choice*. Records that *disclaim* a prediction ("IDENTIFICATION not prediction", "does not PREDICT", "NOT a prediction") are treated uniformly as UNDECIDED — the identification is the open claim — so `PROOF-beta-function-3-times-7`, `INSIGHT-urca-threshold-dim-O`, `PRED-conformal-sound-speed-1-over-3`, `OBS-tenfold-division`, `MEAS-kitaev-z2gauge`, `MEAS-matbg-fragile`, `OBS-mott-parallel` all sit in §4.2/§4.3 (Red Team S3). Nothing is tagged on the strength of what the algebra "should" give. Per #479 AC3 every SELECTED row carries the fixed note **"G₂-trivial: zero independent evidential weight."** — see §5 for the mechanism actually at work in each (fits and scans, not orientation).
