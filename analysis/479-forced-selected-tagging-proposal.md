## 1. Inclusion rule (AC1 scope, mechanical)

An `anchors[]` record is **numeric** iff at least one top-level field **other than** the bookkeeping fields `tier`, `sorry_count`, `pa_local`, `pa_effective` holds a number (int/float, never bool) or a list/dict with **at least one numeric leaf**. String-typed numbers do not count (the schema types `measured_value`/`predicted_value` as `number`). (v0.1 required *all* leaves numeric, which dropped `PRED-a0-redshift-linear` and `PRED-btfr-mass-correction`, whose numbers sit in a mixed `experimental_backing` dict — `F_max_best_fit = 13.378`, `delta_chi2_total = 72.89` — the very fit §3 names; Red Team G1.)

Why this and not "has `measured_source`": the issue's scope is anchors that *cite agreement with an external convention or measurement*. A field test on `measured_source` would miss records that carry the external number in `measured_value` with the citation in prose (`OBS-jades-gs-z14-0-vrot-lower-100`) and would include nothing the numeric test misses. The numeric test is the superset; rows with no external reference on record say so in the table (`— (none on record)`), so completeness is visible rather than filtered.

Fields observed carrying numbers (ledger 6.19.0): `predicted_value` (77), `measured_value` (78), `measured_error` (68), `discrepancy_pct` (39), `predicted_value_lo` (2), `predicted_value_hi` (1), `predicted_values` (1, dict), `F_max_value` (1), `prediction_at_z_14` (1), `synthetic_separation_sigma` (1), `experimental_backing` (4, mixed dict), `literature_constraints` (1, mixed).

**Scope note (Red Team G5):** the 5 R-MEAS rows and the 9 R-EXT rows carry *no QBP-side number*, so there is no "agreement" to tag; they are in the census because the inclusion rule is a superset, and the `basis` column (`measurement-only` / `external-datum`) says so.

**Effective tag (Q4 RULED — the `pa_local` / `pa_effective` pattern).** `alignment_effective` is **computed, never stored**: the weakest link (**min**, with SELECTED < UNDECIDED < FORCED) over the record's own tag and its `prediction_chain` **derivation** closure. Closure nodes contribute: a numeric anchor → its own tag; an `inputs[]` id / `INST-` anchor → SELECTED; a **dangling** id (resolves in no ledger collection) → UNDECIDED-until-resolved, id named; any other resolved node (`axioms`, `derived_principles`, `interpretations`, a non-numeric anchor) → neutral — a root or an ungraded step carries no alignment, exactly as `EffectivePA` folds only over graded anchors; the closure continues through anchors. Hence any SELECTED ancestor ⇒ effectively SELECTED; a FORCED row over an UNDECIDED or dangling ancestor ⇒ effectively UNDECIDED. Only `prediction_chain` is an edge; relevance/mention prose never counts (`docs/cth/qbp-local-extensions.md`, `pa_effective`). Appendix A carries both columns plus `Effective via` (the ancestors at the minimum) and `Dangling`.

**Discipline.** The issue defines FORCED as "uniquely determined by the algebra". This proposal's FORCED is the wider "*no free choice on record* — fixed by an external measurement or external theorem"; to keep the two senses apart every row carries a **`basis`** (Red Team S4): `algebra-identity` · `external-theorem` · `external-datum` · `measurement-only` · `fitted-input` · `calibrated-input` · `candidate-scan` · `unruled`. **No row today is FORCED with an algebra basis** — that is the headline negative, and the schema (§6) makes `basis_kind` a **required** companion of `tag` so the ledger cannot blur it (Q9 RULED). "SELECTED" means *the record itself shows a choice*. Records that *disclaim* a prediction ("IDENTIFICATION not prediction", "does not PREDICT", "NOT a prediction") are treated uniformly as UNDECIDED — the identification is the open claim — so `PROOF-beta-function-3-times-7`, `INSIGHT-urca-threshold-dim-O`, `PRED-conformal-sound-speed-1-over-3`, `OBS-tenfold-division`, `MEAS-kitaev-z2gauge`, `MEAS-matbg-fragile`, `OBS-mott-parallel` all sit in §4.2/§4.3 (Red Team S3). Nothing is tagged on the strength of what the algebra "should" give. Per #479 AC3 every row whose **effective** tag is SELECTED carries the fixed note **"G₂-trivial: zero independent evidential weight."** (an inherited fitted input zeroes the row's independent weight just as a direct one does; per Q5 the sentence lives in the schema `description` of the enum value, not in 28 records) — see §5 for the mechanism actually at work in each (fits and scans, not orientation).
