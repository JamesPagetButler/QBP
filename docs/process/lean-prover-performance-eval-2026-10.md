## Conclusions

Across the four runs attributed to the agent (#493 and #585 by name on the PR; #727 as "builder"; #729 only by the issue #735 body) **no reviewer found a false statement or an unsound proof in Lean the agent produced**. One finding was about proof *robustness*: the 8 `show` steps on #493 welded to PhysLean v4.29.1 internals, brittle at pin bumps (a correct proof carrying technical debt; disposition #504 §4). Every other post-review finding was documentary (docstring and PR-body wording out of step with the measurement record on #727; doc-tag inconsistency and a stale body on #729; an ambiguous accounting sentence on #493) or process (anchor placement on #727/#729; CI pending; an inherited AC on #493). Two of the four runs surfaced real upstream defects the task did not ask for (#492 oracle 1-ULP split; #586 invalid archived octonion table), and both were reported rather than papered over. The first-pass picture is thinner: #493 records "~5 iterations", #729 records 17 inherited errors repaired over an unrecorded number of `lake env lean` iterations (its resource table gives them only as a 4.6–43.8 s range), and #585/#727 record nothing about iteration count. **The measurable gap is accounting, not correctness: zero of the four runs recorded the agent's own tokens or wall-clock**, so the only cost figures that exist are Lean process peaks (and only since the resource gate was enforced, #727/#729) and one orchestrator-reported review cost (128k tokens / 5 min, #735 body). Attribution is the second gap: only #493 and #585 name the agent on the PR; #727 says "builder" and #729 says nothing (it enters this table on the strength of the issue #735 body alone). Three changes follow, all small: (1) the agent's Output section now requires the run's tokens, wall and every Lean invocation's peak RSS (landed in this PR); (2) PR bodies for agent-authored Lean should carry the #585 line — *"Written by a `lean-prover` sub-agent (model), independently verified by the orchestrator: …"*; (3) before review, read every docstring/body number against the measurement file (the S-1/S-2 class on #727 and S1–S3 on #729 would all have been caught by that one pass).
